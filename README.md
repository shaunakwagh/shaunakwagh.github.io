# Portfolio Website (shaunakwagh.github.io)

This repository contains the source for a personal portfolio built with Create React App. The site is designed to be deployed as a static site (GitHub Pages, Netlify, Vercel, etc.).

This README documents how to run the project locally, where to find and update your content, theming, and step-by-step deployment instructions (including using the `docs/` folder or `gh-pages`).

## Project structure

Key files and folders:

- `src/` — React source files
  - `index.js` — app entry
  - `index.css` — global CSS, variables and theme
  - `App.js` — app container, routing and shared layout
  - `data.js` — main content (projects, certificates, links). Edit project entries here.
  - `components/` — React components (About, Projects, Skills, Navbar, Certificates, ThemeToggle, DownloadResume, etc.)
- `public/` — static assets (images, manifest)
- `build/` — generated by `npm run build` (ignored by source control)
- `docs/` — optional: copied build when deploying via `main`/`docs` GitHub Pages configuration

Files you'll commonly edit:
- `src/data.js` — update or add projects, descriptions (accepts arrays for bullet points or string for paragraph), dates, links, images.
- `src/index.css` — color variables, typography and global styles.
- `src/components/*` — adjust component layout or small style tweaks.

## Local development

Install dependencies and run the dev server:

```bash
cd shaunakwagh.github.io
npm install
npm start
```

Open http://localhost:3000 to preview. Changes hot-reload while developing.

## Editing content

- Projects: edit `src/data.js` and find the `projects` array. Each project may look like:

```js
{
  name: 'AI Document Retrieval System (RAG)',
  tagline: 'RAG search with LangChain + FAISS',
  date: '2024',
  link: 'https://example.com',
  image: '/path/to/image.png',
  description: [
    'Built an LLM-backed retrieval system using FAISS.',
    'Used LangChain for orchestration and Gradio for a demo UI.'
  ]
}
```

- The `description` field supports either:
  - an array of strings (renders as bullet points), or
  - a single string (renders as a paragraph).

- Badges used in the About component are inline spans; update labels and colors in `src/components/About.js`.

## Theming and colors

- Global colors and typography live in `src/index.css` as CSS variables. Example variables:

  - `--brand-light`, `--brand-medium`, `--brand-dark`
  - `--success-*`, `--warning-*`, `--alert-*`
  - `--neutral-xlight`, `--neutral-dark` and `--background`, `--text`

- Dark mode is supported via a `[data-theme="dark"]` selector. The app's `ThemeToggle` component stores the theme in `localStorage` and toggles the `data-theme` attribute on `document.documentElement`.

To change the core palette, update `:root` variables in `src/index.css` and the dark overrides under `[data-theme="dark"]`.

Accessibility: color contrasts were chosen to meet WCAG AA where possible. If you change colors, verify contrast for text/background using a tool like https://contrast-ratio.com/.

## Build & publish (recommended options)

You are currently publishing from the `main` branch. If you see the README when visiting your Pages site, that likely means GitHub Pages is serving the branch/folder that contains only README.md rather than your built `index.html`.

Two recommended deployment approaches:

### Option A — Publish `build/` into `docs/` on `main` (simple)

1. Build and copy the output to `docs/` then push:

```bash
npm run build
# remove old docs then copy the new build
rm -rf docs && cp -R build docs
git add docs
git commit -m "Publish site: copy build to docs"
git push origin main
```

2. On GitHub: Settings → Pages → Set Source to `main` branch / `docs` folder. Save.

3. Wait ~1 minute and refresh your site URL. Clear browser cache if needed.

This is the approach you've been using and is quick for manual deploys.

### Option B — Use `gh-pages` package (automated)

1. Install `gh-pages` and add scripts to `package.json` (example):

```json
"homepage": "https://<your-username>.github.io/<repo-name>",
"scripts": {
  "predeploy": "npm run build",
  "deploy": "gh-pages -d build"
}
```

2. Run:

```bash
npm install --save-dev gh-pages
npm run deploy
```

This pushes a `gh-pages` branch containing `build/` and GitHub Pages will serve it automatically.

## Troubleshooting

- If your page shows the README instead of the site:
  - Confirm Pages source in repo Settings (branch + folder)
  - Ensure `index.html` exists in the folder being served (`docs/` or branch root)
  - Hard-refresh browser (Cmd+Shift+R) or open in incognito

- If a change doesn't appear:
  - Confirm `git status` and `git log -1 --oneline` to ensure the commit was pushed
  - If you're using `docs/` approach, confirm updated `docs/index.html` is in the `main` branch
  - Check GitHub Pages build/deploy logs in the repo Settings → Pages
